## 1. Research already done — do NOT re-derive it

### 1.1 Named pipes (the whole point of M1)

Dolphin compiles a pipe input backend into **every Unix build**
(`if(UNIX) add_definitions(-DUSE_PIPES=1)`), mainline.

```ini
# GCPadNew.ini
[GCPad1]
Device = Pipe/0/p1
```

ASCII protocol, newline-terminated, written to the FIFO:

```
PRESS A          RELEASE A
SET L 1.0        SET MAIN 0.5 0.5     # 0.5 0.5 == centre
```

**Why this and not uinput**: a pipe binds by **file name**. Player 2 is player 2
because we named the file `p2` — not because an enumeration happened to hold that
order. Four identical virtual pads under evdev are distinguished only by an
integer that changes on hotplug; that single fact produced most of the input pain
we hit before this project existed.

Constraints, all confirmed:
- FIFOs must exist **before** Dolphin starts (`mkfifo` first, then spawn).
- Mainline opens them `O_NONBLOCK` → **no frame-sync guarantee**. Acceptable
  here: the last input wins, and the next frame is ~8 ms away.
- GameCube-shaped inputs only — no Wiimote pointer/motion.
- Keep **one persistent write fd per pipe**. Reopening per write is a syscall on
  the hot path and races the reader.

### 1.2 Headless flags

```bash
dolphin-emu-nogui -p headless -v Vulkan -e /path/to/game.rvz
```

- **`-p headless` is mandatory, explicitly.** Without `-p`, the Linux fallback is
  `x11 → fbdev → headless` with **no retry**, and `PlatformX11::Init()` calls
  `XOpenDisplay(nullptr)` — which fails on a server with no display. The symptom
  is a startup error that looks like a build problem and is not.
- **Rendering stays complete in headless**; only *presentation* is short-circuited
  (`Presenter::Present()` returns early). EFB, XFB, shaders and draws all run.
  This is what makes M2 possible later.
- Vulkan headless needs **neither a surface nor a swapchain**
  (`enable_surface = wsi.type != WindowSystemType::Headless`), which is cleaner
  than `VK_EXT_headless_surface` and works on any conformant driver.
- **Precedent**: `libmelee` / `slippi-ai` have run mainline headless Dolphin
  instances in parallel for years. This path is well travelled.

### 1.3 Dolphin must be built from source

Verified on lgf 2026-08-10:
- **No `dolphin-emu` apt package** on this release (`Candidate: (none)`).
- The Games-on-Whales AppImage **does not contain `dolphin-emu-nogui`** — only
  the GUI binary.

`docker/Dockerfile.dolphin` builds it with `ENABLE_QT=OFF ENABLE_NOGUI=ON` and
ends with `test -x .../dolphin-emu-nogui` so the build **fails loudly** if that
flag ever stops producing the binary.

## 2. Unknowns that were resolved FIRST (risk-first ordering) — ✅ all four

Kept as written, because the reasoning for *why* each was worth checking early is
still the reasoning M2 should copy. Answers and measurements are in §0.

1. **Does the Dolphin build succeed with our flag set?** The `test -x` answers it.
   Budget ~20-40 min on a Ryzen 5 3600. It caches, so it is a one-time cost.
2. **Do pipes work on a headless instance?** A documented *input-gate* bug exists
   in the GUI/X11 world: hotkeys and browser pads die together when the render
   window never gains focus. Pipes should bypass the focus path entirely — but
   **verify it, do not assume it**. This is the single biggest risk to M1.
3. **What exactly must `GCPadNew.ini` contain** for a pipe device? Establish the
   minimal working file and commit it as a fixture.
4. **Does `-p headless` still produce frames we can capture in M2?** Research says
   yes. Confirm cheaply now (e.g. a frame-dump flag) rather than discovering it
   two weeks later.

### The mutation pass, and the test it caught

Five deliberate bugs were reintroduced to check the tests fail for the right
reason. Four were caught immediately. **One was not**:
`a_dropped_frame_does_not_desynchronise_the_diff` passed even with the bug
(committing the encoder's state after a failed write) restored — because it
sent a *different* follow-up frame, which re-derives those fields anyway. Only
re-sending the **identical** state distinguishes "we kept Dolphin's real state"
from "we recorded one it never received". The test was rewritten and now fails
as it should.

That is the rule earning its keep: the test looked correct, read correctly, and
proved nothing.

### Known limitation, stated rather than implied

If the **worker** is `SIGKILL`ed, Dolphin survives it. The usual fix is
`prctl(PR_SET_PDEATHSIG)` via a `pre_exec` hook, which is `unsafe` and therefore
out of bounds until M2's FFI module justifies it properly. `Session::shutdown`
and the `Drop` fallback cover every exit the worker can observe; M3's container
boundary is the real answer.

## 4b. Manual verification procedure

Two scripts, both committed, both usable without the Rust toolchain:

```bash
docker build -f docker/Dockerfile.dolphin -t nel3ab/dolphin:dev .   # ~25 min, cached
docker/smoke-pipes.sh 40          # hand-written FIFO + ini: is the pipe wired at all?
```

For the full "the game reacted" proof, start Dolphin with frame dumping and run
the analyser (this is what the integration test automates):

```bash
python3 docker/prove-input-reaches-the-game.py "$SESSION_DIR"
# BASELINE -> CONTROL -> PRESS A -> RESULT: PASS
```

The automated version, on a machine with a GPU and the ROM:

```bash
cargo test -p nel3ab-emulator --features dolphin-integration -- --nocapture --test-threads=1
```

It is feature-gated because a test that cannot run is worse than no test: it
would report a pass in CI, on a machine with neither GPU nor ROM.

## 5. Traps already paid for — do not step in them again

### Paid for during M1 (2026-08-10)

- **Docker's default 64 MiB `/dev/shm` kills Dolphin with SIGBUS.** Exit 135,
  **no log line, no message**. The user directory gets created and the Vulkan
  shader cache gets populated first, so it looks like a successful start that
  vanished. `--shm-size=2g` fixes it; Dolphin's emulated-memory arena is backed
  by shared memory and does not fit in the default.
- **Almost every Dolphin misconfiguration fails in *silence*.** There is a
  pattern here worth internalising: a malformed pipe command, an `.ini`
  expression that binds nothing, a FIFO created after startup, and a `-C`
  override naming an unknown system are **all** discarded without a word. Nothing
  logs, nothing exits non-zero — the button simply never presses. This is why the
  crate asserts byte-exact output and validates `-C` parts up front.
- **`-b`/`--batch` does not exist in `dolphin-emu-nogui`.** It is registered only
  when the parser is built *with* GUI options, and nogui passes `OmitGUIOptions`.
  Passing it is a hard CLI error.
- **The `-C` system names match neither the enum nor the file.** It is
  `Dolphin.<Section>.<Key>` for `Dolphin.ini` (the enum is `System::Main`) and
  `Graphics.…` for `GFX.ini` (the enum is `System::GFX`). A wrong name is dropped
  silently — see above.
- **Frame dumping needs two switches in two different files**:
  `Dolphin.Movie.DumpFrames=True` (the master switch, *not* a Graphics setting)
  and `Graphics.Settings.DumpFramesAsImages=True` for PNGs instead of an AVI.
- **`Start` and `START` are both correct, in different files.** The `GCPadNew.ini`
  key is `Buttons/Start`; the pipe token is `START`. Using one spelling in both
  places yields a button that never presses.
- **Never hash the newest framedump file** — it is still being written. A torn
  PNG is indistinguishable from the screen changing, and produced a false
  "the screen changed by itself" that voided a run. Read a frame ~8 behind the
  newest *and* require the trailing `IEND` chunk.
- **`cmake --install` puts the data in `Sys`, capital S** (`/usr/share/dolphin-emu/Sys`).
  A lowercase assertion failed the image build after the 25-minute compile.
- **`just audit` was red before M1 touched anything** — our own AGPL crates were
  being checked against the third-party allow list, and workspace `path` deps
  were counted as wildcards. Fixed in `deny.toml` via `private.ignore` and
  `allow-wildcard-paths`. Run all four gates, not just `just check`.

### Paid for earlier

- **A stray `enum.py` in `/tmp` shadows the standard library.** Python adds the
  script's directory to `sys.path`, so any `python3` run from that directory
  breaks with `module 'enum' has no attribute 'global_enum'`. Never name a helper
  script after a stdlib module.
- **`ssh host ~/script` expands `~` on the LOCAL machine.** Use absolute paths.
- **Wolf rewrites its own `config.toml`** and may reflow a single-line array into
  many lines. **Parse it, never `sed` a line number** — doing so left orphan lines
  and crash-looped Wolf.
- **Do not restart every media container at once**: it triggers simultaneous
  library rescans over NFS and stalls the machine for minutes.
- **Quote heredocs and avoid nested quotes in `ssh '...'`** — write a script to a
  file and `scp` it. Inline quoting cost several failed runs.
- Prefer `timeout` on every remote command: a hung NFS or a slow `docker exec`
  otherwise blocks the whole session.

## 6. Standards reminder (see `CLAUDE.md`)

- No rule without its reason, and the reason is **measured**.
- A negative twin for every positive assertion; red-first for every bug fix.
- Make invalid states unrepresentable before writing a runtime check.
- The binary orchestrates; behaviour lives in library crates.
- The worker must not panic — a panic kills a live game session.
- Conventional Commits with an emoji. **Never** add AI attribution.
